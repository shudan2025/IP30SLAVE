# SVN Deployment

## Status and endpoints

SVN is deployed with `deploy/svn/compose.yaml` and a locally built image, `ip30-svn-apache-ldap:1.0.0`. It uses Ubuntu 24.04, Apache `mod_dav_svn`, LDAP authentication, and Subversion tools. The README-listed `garethflowers/svn-server:latest` image was blocked by the registry allowlist and did not provide the required LDAP integration; no allowlist bypass was used.

Caddy serves repositories over HTTPS at URLs such as `https://<server-ip>/svn/main`. The service is attached to the private LLDAP and Mailserver Docker networks and has no published host port; port `3690` is not open. The `ip30-svn-data` named volume stores the automatically created `main` repository.

## Deployment

Sync the `deploy/svn/` and `deploy/caddy/` directories to their service deployment directories. The public `/svn` route and index entry are generated by `deploy/caddy/render-config.py`; export the Caddy root certificate before building SVN.

```sh
sudo python3 /opt/ip30slave/caddy/render-config.py
cd /opt/ip30slave/caddy
sudo docker compose --env-file .env -f compose.yaml up -d --no-deps --force-recreate caddy
sudo python3 /opt/ip30slave/caddy/export-caddy-ca.py
cd /opt/ip30slave/svn
sudo docker compose --env-file .env -f compose.yaml config -q
sudo docker compose --env-file .env -f compose.yaml up -d --build svn
```

The service uses its own protected `.env` for LDAP bind settings; notification addresses default to `postmaster@agigactu.com` unless overridden.

## LLDAP authentication and authorization

Apache's LDAP search uses LLDAP's unique `mail` attribute for the login name and maps the authenticated user to `uid` for repository authorization. LDAP traffic uses `ldap://lldap:3890` over the private `ip30-lldap-apps` network; LLDAP TLS is disabled in this candidate. The current server uses `LDAP_BIND_DN` and `LDAP_BIND_PASSWORD` from the protected `/opt/ip30slave/svn/.env`; the service-scoped template is `deploy/svn/.env.example`. Replace the LLDAP administrator bind with a least-privilege read-only service account before production.

The mounted `deploy/svn/authz` policy grants authenticated users read access and grants write access only to UID `admin`. The built-in LLDAP `admin` account has no `mail` attribute, so it cannot use the email-only login until its profile is completed. Before employee use, grant write access to the intended UIDs/groups in `authz`, then recreate the SVN service to reload the policy:

```sh
cd /opt/ip30slave/svn
sudo docker compose --env-file .env -f compose.yaml up -d --no-deps --force-recreate svn
```

## Commit notifications

The `main` repository has a post-commit hook that sends revision summaries through `mailserver:25` on the private `ip30-lldap-mail` network. The container entrypoint writes the non-secret `SVN_NOTIFICATION_TO`, `SVN_NOTIFICATION_FROM`, `SVN_SMTP_HOST`, and `SVN_SMTP_PORT` settings to a hook-readable config file because Apache does not pass the Compose environment through to Subversion hooks. The default sender and recipient are `postmaster@agigactu.com`. SMTP is unauthenticated and unencrypted on that private network.

## SVN client TLS

Clients must trust the exported Caddy root certificate. The tested Subversion 1.14.3 client still reported a hostname mismatch for the Caddy IP certificate, even though its SAN contains the server IP. With the root CA explicitly trusted, this client required the narrow `cn-mismatch` override:

```sh
svn --config-option=servers:global:ssl-authority-files=/path/to/caddy-root.crt \
  --trust-server-cert-failures=cn-mismatch \
  --username employee@example.com \
  ls https://<server-ip>/svn/main/
```

This override relaxes only hostname matching; the Caddy CA remains trusted. Prefer a DNS URL and certificate name supported by all clients when available.

## Validation

The image built successfully and Apache configuration passed validation. `/svn` redirects to `/svn/`; anonymous access to `/svn/main/` receives HTTP 401 with a Basic authentication challenge. A temporary LLDAP email user authenticated and committed revision 1 to a temporary repository over HTTPS through Caddy. The post-commit notification arrived in the test Mailserver mailbox. The synthetic user, temporary repository, temporary ACL, and notification were removed afterward. The final container was recreated from the production image, without the temporary LDAP test utilities.
